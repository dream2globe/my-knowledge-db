## 핵심 요약

Claude Code와 같은 내장 하네스 도구 위에 프로젝트만의 '커스텀 하네스'를 구축하여 바이브 코딩의 품질을 극대화하는 실전 가이드입니다. CLAUDE.md와 기획 문서(PRD, 아키텍처, ADR)로 컨텍스트를 통제하고, 페이즈(Phase) 단위 자동 실행 파이프라인과 Hooks를 통한 자동 검증 시스템을 세팅하는 구체적인 프레임워크 사용법을 라이브 데모와 함께 설명합니다.

---

## 상세 내용

### 1. 내장 하네스와 커스텀 하네스
- **이미 내장된 하네스**: Claude Code, Codex 등 최신 AI 코딩 도구는 시스템 프롬프트 차원에서 위험 명령어 차단, 컨텍스트 보존 등의 '범용 하네스'가 이미 구축되어 있습니다.
- **커스텀 하네스의 필요성**: 범용 도구는 내 프로젝트만의 도메인 규칙, API 사용 방식, 배제할 기술 등을 모릅니다. 따라서 범용 하네스 위에 나만의 규칙과 문서를 제공하는 얇은 레이어(커스텀 하네스)를 올려야 AI의 코딩 결과물 품질이 급격히 향상됩니다.
- **오픈소스 활용**: `oh-my-claudecode`처럼 19개의 전문화된 에이전트와 파이프라인이 세팅된 오픈소스를 활용할 수도 있으나, 내 프로젝트의 맥락을 반영하기 위해서는 결국 직접 기획 문서를 채워야 합니다.

### 2. 하네스 프레임워크 4대 레이어
- **docs/ (프로젝트의 뇌)**: 
  - **PRD**: 목표, 핵심 기능 및 **MVP 제외 사항**을 명확히 적습니다. 제외 사항이 없으면 AI가 불필요한 기능까지 무작정 만들려 합니다.
  - **ARCHITECTURE.md**: 디렉토리 구조, 데이터 흐름, 설계 패턴을 명시합니다.
  - **ADR (Architecture Decision Record)**: 해당 기술이나 구조를 선택한 이유와 포기한 트레이드오프를 남깁니다.
- **CLAUDE.md (프로젝트 헌법)**: 반드시 지켜야 할 규칙(우선순위 Critical), 외부 API 호출 방식 등을 적습니다.
- **실행 파이프라인 (/harness & execute.py)**: `/harness` 명령을 통해 문서를 읽고 작업을 여러 Phase로 쪼갭니다. 이후 `execute.py`가 헤드리스 모드(`claude -p`)로 각 Phase를 순차 실행하며, 상태를 JSON 파일로 기록하여 컨텍스트 분리와 추적을 동시에 해결합니다.
- **Hooks (자동 검증)**: AI가 실수하기 전에 차단하는 장치입니다.
  - **TDD Guard**: 테스트 코드를 먼저 작성하지 않으면 구현을 막습니다.
  - **Dangerous Command Guard**: `rm -rf`나 메인 브랜치 강제 푸시를 차단합니다.
  - **Circuit Breaker**: 루프를 돌 때 무한 루프에 빠지는 것을 방지합니다.

### 3. 기획의 중요성과 Spec-driven Development
- 바이브 코딩에서 가장 많은 시간을 투자해야 하는 부분은 기획 단계입니다.
- 첫 플랜을 절대 믿지 말고, AI에게 "에러 핸들링 추가해", "UX 관점에서 부족한 점 보강해" 등 5~6회 이상 반복적으로 요구하여 문서를 촘촘히 채우는 것이 필수입니다. 
- 기획이 완벽한 구조(JSON 등)로 잡히면, AI가 알아서 검증하고 수정하는 **랄프 루프(Ralph Loop)**를 밤새 돌려 개입 없이 앱을 완성할 수 있습니다.
